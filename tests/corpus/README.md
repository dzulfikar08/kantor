# Test corpus

Files for round-trip and fidelity tests (plan.md §5, §7). Every file must be listed here with its source and licence. **Never add private documents**, and don't add third-party files without checking their licence first.

## `xlsx/`

All files are **generated by this repository** and dedicated to the public domain under **CC0-1.0**: `01`–`12` with [`scripts/corpus/gen_xlsx.py`](../../scripts/corpus/gen_xlsx.py) (Python standard library only, raw SpreadsheetML, deterministic output), `13`–`17` with [`scripts/corpus/gen_features_xlsx.py`](../../scripts/corpus/gen_features_xlsx.py) (XlsxWriter, pinned version, from data made up in the script; deterministic), `19` with [`scripts/corpus/gen_validation_xlsx.py`](../../scripts/corpus/gen_validation_xlsx.py) (standard library, raw SpreadsheetML; deterministic), `20` with [`scripts/corpus/gen_charts_xlsx.py`](../../scripts/corpus/gen_charts_xlsx.py) (XlsxWriter, pinned; deterministic), `21` with [`scripts/corpus/gen_pivot_xlsx.py`](../../scripts/corpus/gen_pivot_xlsx.py) (standard library, raw SpreadsheetML: XlsxWriter can't write pivot tables; deterministic). Formula cells carry cached values computed by the generator the way Excel would, so tests can compare engine results against "what Excel stored".

Also in `xlsx/`:

- `expectations.tsv` (generated): what Excel displays for formatted cells, and the column widths, row heights and frozen panes the generator wrote.
- `features.tsv` (generated by `gen_features_xlsx.py`): one line per feature of files `13`–`17`, with the part it lives in and an XML probe. The test checks each probe in the original, after open → save, and after saving the saved file again (check `feature`).
- `known-gaps.tsv` (hand-maintained): fidelity findings that are known IronCalc gaps, each with a reason.

## How the test works

`crates/sheets_engine/tests/corpus.rs` (part of `cargo test --workspace`) opens every file with `sheets_engine::Workbook`, saves and reopens it, and compares inputs and displayed values of every used cell. It also reads the original and the saved file independently with calamine (values, formulas, styles, merges, names, links) and checks layout, comments and zip parts, so it catches both IronCalc import losses and export losses. Each difference is a finding; findings not in `known-gaps.tsv` fail the test, and so do listed gaps that no longer happen.

`crates/sheets_engine/tests/structure.rs` opens files `13`–`16`, inserts or deletes rows and columns, saves, and checks that carried parts moved with them (validations, sparklines, charts, drawing anchors, notes and their boxes, page breaks, tables, the filter range).

```sh
cargo test -p sheets_engine --test corpus -- --nocapture       # report on stdout
KANTOR_CORPUS_OUT=/tmp/fid cargo test -p sheets_engine --test corpus   # + round-tripped files and report.md
KANTOR_CORPUS_BLESS=1 cargo test -p sheets_engine --test corpus  # rewrite known-gaps.tsv (keeps reasons; new lines get TODO)
python3 scripts/corpus/gen_xlsx.py           # regenerate after editing the generator
python3 scripts/corpus/gen_xlsx.py --check   # CI: committed files match the generator
python3 scripts/corpus/gen_validation_xlsx.py [--check]   # file 19
uv run --with xlsxwriter==3.3.1 scripts/corpus/gen_features_xlsx.py           # files 13-17 + features.tsv
uv run --with xlsxwriter==3.3.1 scripts/corpus/gen_features_xlsx.py --check   # CI
uv run --with xlsxwriter==3.3.1 scripts/corpus/gen_charts_xlsx.py [--check]   # file 20
python3 scripts/corpus/gen_pivot_xlsx.py [--check]   # file 21
```

CI (`.github/workflows/fidelity.yml`) runs the test on x86_64, puts the report in the job summary, and uploads LibreOffice-headless PDFs of each original and round-tripped file as the `fidelity-xlsx` artifact.

To add a case, extend the generator (one function per file), regenerate, run the test, and document any new finding in `known-gaps.tsv` (or fix it).
