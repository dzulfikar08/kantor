# kantor.paparanai.id

The download site for Kantor, in English (`/`) and Indonesian (`/id/`). Plain static HTML,
CSS and a little vanilla JavaScript, generated by one Node script with no dependencies.

## Build, preview, deploy

```sh
node site/build.mjs                          # writes site/dist (Node 18 or later)
python3 -m http.server 4329 -d site/dist     # preview at http://localhost:4329
```

Deploy to Cloudflare Pages (project `kantor-site`, custom domain `kantor.paparanai.id`):

```sh
node site/build.mjs
CLOUDFLARE_ACCOUNT_ID=b7e6f8457bd39fa37a7eea5249799754 wrangler pages deploy site/dist --project-name kantor-site --branch main
```

`site/dist` is not committed; always build before deploying.

## Layout

```
build.mjs          page template, asset fingerprinting, 404 page, checks (no em dashes, every
                   English string has an Indonesian one)
src/strings.mjs    all text, English and Indonesian
src/site.css       styles (tokens follow crates/kantor_ui: tokens.rs, metrics.rs)
src/site.js        OS detection, latest-release line, screenshot tabs, copy button
src/img/           screenshots (AVIF, WebP, PNG at 800 and 1550 px) and og.png
static/            copied as-is: _headers, robots.txt, sitemap.xml, favicons
tools/             how the screenshots and the OG card are made (see below)
```

## What the script does

Everything works without JavaScript: the main button then reads "Choose your download" and
jumps to the download section. With JavaScript:

- **Which computer.** `navigator.userAgentData` (and its `architecture` hint on Chromium), else
  the user agent. Mac gets `Kantor.dmg`; Linux gets the x86_64 or aarch64 AppImage; Windows and
  phones get a plain note and a link to the download section. The visitor's platform card is
  moved first in the DOM (so tab order matches what you see) and labelled.
- **Latest version.** Fetches `api.github.com/repos/dzulfikar08/kantor/releases/latest` (cached
  in `sessionStorage` for 10 minutes, 8 s timeout). Shows tag and date; on an error or rate
  limit it says it couldn't check, and the buttons keep their `releases/latest/download/…`
  links. If the latest release doesn't contain `Kantor.dmg`, `Kantor-x86_64.AppImage` or
  `Kantor-aarch64.AppImage`, a note next to that button links to the release page instead,
  and the main button falls back to the download section.

**Until a release with those file names exists (planned for v0.2.0), the download buttons
lead to GitHub 404 pages.** The site says so next to each button while v0.1.0 is the latest.

## Security headers and caching

`static/_headers`: a strict CSP (`default-src 'none'`, scripts and styles from the site only,
`connect-src https://api.github.com` for the version check), `nosniff`, `frame-ancestors 'none'`,
HSTS, a restrictive Permissions-Policy. CSS and JS have content hashes in their names and are
cached for a year; images for a day; HTML uses Cloudflare's default (revalidate). No analytics
or third-party requests apart from the GitHub API call.

## Screenshots

They are real Kantor windows on Linux, captured with `grim` from Hyprland:

```sh
KANTOR_BIN=$PWD/target/release/kantor PY=/path/to/venv/bin/python site/tools/shots.sh
```

`shots.sh` generates three sample files (`make_samples.py`, made-up content: a formatted sales
workbook in rupiah, a short report with a list, a picture and a table, and a four-slide deck with
gradients, chevrons, a table and a chart) and opens each in its own Kantor with throwaway config,
state and socket directories (your settings and session are never touched; update checks are
off), in the Catppuccin (dark) and Catppuccin Latte (light) Omarchy themes. Kantor runs on a
private headless Hyprland output (`KSITE`, 1600×1000 at 125 %, removed afterwards), so nothing
appears on your screen and focus never moves. A selection (Sheets) and the slide to show
(Slides) are set through Kantor's own MCP server (`mcp_call.py`), and the window is captured with
`grim -T` (just that window, no notifications or cursor), then closed. `images.sh` converts the
captures in `tools/shots/` to the site's formats and `og.sh` renders the 1200×630 card. The
repository README uses the same WebP files.

`formula_shot.sh` (run after `shots.sh`) takes the README's extra Sheets picture of a formula
being typed, with its references coloured: Kantor runs in a private Xwayland server on its own
headless output and `xdotool` types into it, so your keyboard and focus are never used. Output:
`docs/images/sheets-formula-{dark,light}.webp`.

Column widths in the sample workbook are multiples of 4 characters (36 px) so that column edges
fall on whole pixels at 125 %; otherwise merged cells show a 1 px seam.

The site shows the dark captures to visitors whose system is dark and the light ones otherwise
(`<picture>` with `prefers-color-scheme`).
